# Completed Backlog Items

Items that were in the backlog and have been completed.

- [x] **Discovered containers in room description**: When a hidden container is revealed, show it in the room description. Implementation: Add `revealedText` field to containers (e.g., "Under the root of a nearby tree you see a leather pouch."). Split room descriptions into main description + navigation sentence (last sentence). When rendering, concatenate: main description + revealed container texts + navigation sentence. This keeps discovered things naturally woven into the description rather than listed separately.

- [x] **Put items in containers**: Add `put <item> in <container>` command to move items from player inventory into an open container in the room.

- [x] **Better "get" error for non-items**: When player tries to `get <feature>` or `get <container>`, reply "You can't take that." instead of "There's no X here." Checks visible features and containers in the room before returning the generic "not found" message.

- [x] **Add small features**: Added 19 interactive features across all 5 rooms - Town Square (fountain, statue, moss, cobblestones), Rusty Tankard (fireplace, oak counter, mounted trophy, dartboard), Village Market (merchant stalls → loose board → hidden compartment chain, spice barrels, notice board), Forest Path (ancient oaks, rustling undergrowth, trail markers), Forest Clearing (mushroom ring → hidden cache chain, gnarled tree, soft moss, strange sounds). Standardized trigger verbs documented in backlog.

- [x] **Multiple simultaneous attackers**: Allow multiple monsters to attack a player at once. Implemented staggered engagement: first monster attacks after 3-5 seconds, additional monsters join every 3-5 seconds. Flee mechanics use highest-level monster for DC (already implemented). Added `clearPendingAggro()` to cancel pending attacks when player leaves room or disconnects. Modified `initiateCombat()` to allow monsters to join existing player combat via `addMonsterToCombat()` helper.

- [x] **iPad/mobile testing**: Set up ngrok tunneling for mobile device testing. Added `client/.env.example` with `VITE_API_URL` and `VITE_SOCKET_URL` variables. Created `MOBILE_TESTING.md` with step-by-step instructions. Updated server CORS to allow ngrok origins and local network IPs.

- [x] **Virtual scrolling**: Added @tanstack/react-virtual to ChatPanel for efficient rendering of large message lists. Uses dynamic row measurement for variable-height messages, preserves smart auto-scroll behavior (only scrolls when user is at bottom), and renders ~5 overscan items above/below viewport for smooth scrolling.

- [x] **Item and container sizes**: Added t-shirt size system (tiny=0, small=1, medium=2, large=3, huge=4) to items and containers. Items can only be placed in containers where `item.size < container.size`. Players cannot take huge items. Added `size` field to both `items` and `containers` tables in schema. Updated seed data with appropriate sizes (coins=tiny, potions=small, swords=medium, greatswords=large). Deferred portable container implementation (isContainer, itemInventory table) to later.

- [x] **Back equipment slot**: Added "back" equipment slot for backpacks/cloaks. Updated schema, types, and equipment service. Added aliases: back, backpack, cloak, cape. Future: backpacks could expand inventory capacity if inventory limits are implemented.

- [x] **Unified "can't do that" messaging**: Created `EntityResolver.ts` that searches all visible entity types (items, monsters, NPCs, players, features, containers, corpses) in parallel and returns "wrong_type" when a match exists but isn't valid for the action. Updated `handleAttack`, `getItem`, `getItemFromContainer`, `putItemInContainer`, `openContainer`, and `closeContainer` to use it. Now "attack fountain" returns "You can't attack the fountain" instead of "You don't see fountain here".

- [x] **Display equipment bonuses in stats**: Show stat bonuses from worn items in the `stats` command output. Stats display with inline bonuses (e.g., "STR: 12 (+2)") and an "Equipment Bonuses" section lists each item's contribution.

- [x] **Attribute point spending command**: Added `train <stat>` command to spend unspent attribute points. Shows current points and stats with no args, spends 1 point to increase a stat with `train str/dex/con/int/wis/cha`. Stats capped at 99. Also aliased as `spend`. Created new `handlers/character.ts` for character-mutating commands (separate from info commands).

- [x] **Per-player discoveries**: Added personal discovery system where some hidden features/containers are only visible to the player who discovered them. Added `discoveredFeatureIds` and `discoveredContainerIds` JSON arrays to players table. Added `discoveryScope` field to features and containers tables (null/"global" = revealed for everyone with time-based re-hiding, "personal" = only visible to discoverer, permanently stored on player record). Updated `getFeaturesInRoom`, `getContainersInRoom`, `revealFeature`, `revealContainer`, and `getRoomWithContents` to support personal discoveries. Added example personal discovery feature in Forest Clearing (hidden nook requiring WIS 12 check).

- [x] **Dice roll display toggle**: Added `toggle rolls` (or `toggle dice`) command to show/hide dice roll details. When enabled, displays roll info below messages in gray, right-aligned. For feature checks: `d20+0 = 15`. For combat attacks: `Attack: d20+3 = 18  |  Damage: 1d6+2 = 7`. Roll info only shown to the player making the roll. Added `UserPreferences` type with `showRolls` field, stored as JSON in `users.preferences` column. Created unified `rollD20WithDetails()` and `rollDamageWithDetails()` functions in DiceService for consistent roll info generation across the codebase.

- [x] **Level up feat slot notification**: When a player levels up and gains a feat slot (every even level: 2, 4, 6, etc.), include a message about the new feat slot and hint to use "feats" command. Added `gainedFeatSlot` boolean to level_up event, set in CombatService when granting feat slot, and handlers.ts sends additional private message: "You gained a feat slot! Use 'feats' to see your options."

- [x] **Toughness feat HP display**: Fixed Toughness feat not updating max HP when acquired. Created `recalculateAndUpdateMaxHp()` utility in StatService.ts that recalculates max HP based on current stats, equipment, and feats, then updates the database. Supports two modes: "heal_gained" (for level up, training, feats) and "preserve_damage" (for equip/unequip). Updated `acquireFeat()` to call this utility when acquiring HP-affecting feats (effectType === "hp_bonus"). Now acquiring Toughness immediately updates maxHp and currentHp in the database, and shows the HP gain in the success message.

- [x] **Equipment bonuses → attack/damage/AC instead of stats**: Changed equipment from stat-based bonuses (strEffect, conEffect) to direct combat bonuses (attackBonus, damageBonus, acBonus). Added three new columns to items table. Updated StatService with `calculateEquipmentACBonus()`, `calculateEquipmentAttackBonus()`, `calculateEquipmentDamageBonus()`. AC calculation now uses equipment AC bonus directly instead of deriving from CON. CombatService includes equipment attack/damage bonuses in hit/damage rolls. Stats command shows Attack and Damage bonuses with breakdown. Seed data updated: rusty sword has attackBonus: 1, damageBonus: 1; leather cap has acBonus: 1. Stat-boosting items (strEffect, conEffect, etc.) remain available for future items like Belt of Giant Strength.

- [x] **Examine monsters**: Refactored `handleExamine` to use `resolveEntity` for unified entity lookup. Now supports examining monsters (shows description + health status like "healthy", "wounded", "near death"), NPCs (shows description), and other players (shows stats/equipment). Also added helper functions `getHealthStatus()`, `examinePlayer()`, and `examineCorpse()` for cleaner code organization.

- [x] **Shout range**: Changed `shout` to only reach adjacent/connected rooms instead of region-wide. Shout now broadcasts to the current room plus all rooms connected via exits. Added `announce` admin command for region-wide broadcasts (the old shout behavior). Updated ChatService with new `adjacentRooms` scope type and `announce()` function. Updated tests to verify adjacent room targeting.

- [x] **Dual wielding penalties**: Implemented -4 attack penalty for dual wielding and two attacks per turn. Each weapon's damage dice and bonuses resolve separately (no stacking of magic weapon bonuses). Main hand attack happens first; if it kills the target and there are more opponents, off-hand attack hits the next target. Updated `CombatParticipant` type to store per-weapon data (`mainHandWeapon`, `offHandWeapon`) instead of aggregate bonuses. Stats command shows per-weapon attack/damage bonuses when dual wielding (e.g., "Attack: +2/+1 (dual wield -4)"). Requires Two-Weapon Fighting feat to equip weapons in both hands (already implemented).

- [x] **Add "loot" as alias for "get all from"**: Added `Command.Loot` enum, alias mapping, and `handleLoot` handler that transforms "loot corpse" into "get all from corpse". Registered in command registry.

- [x] **Wearing already-equipped item gives confusing message**: Added check in `equipItem()` to detect when the item being equipped is already worn in the target slot. Returns "You're already wearing that." instead of the confusing swap message.

- [x] **"look <myPlayerName>" should resolve to "look self"**: Already working - `handleExamine` checks if target matches player name (case-insensitive) and routes to self-examination logic.

- [x] **Show direction when player leaves**: Updated `room:leave` broadcast in `handleMove` and `handleFlee` to include `direction` field. Client's `handleRoomLeave` now shows "Fox leaves to the north." instead of "Fox has left."

- [x] **No broadcast when player picks up item**: Added broadcast in `handleGet` when item pickup succeeds. Other players see "Fox picks up a rusty sword." (or quantity + plural name for stacks).

Self-examination shows full stats; examining others shows only name, level, and visible equipment. Changed "You don't have anything equipped" to "They don't have anything equipped" for other players.

- [x] **Equip fuzzy match should prioritize unequipped items**: Added `excludeItemIds` option to `findItemInPlayerInventory()` that sorts matching items so excluded IDs come last. `equipItem()` now passes currently equipped item IDs to prefer unequipped duplicates when fuzzy matching.

- [x] **"look <item>" should check inventory**: Extended `EntityResolver.resolveEntity()` to accept optional `playerId` parameter. When provided, `findItem()` searches both room inventory and player inventory. `handleExamine` now passes `player.id` to `resolveEntity()`, allowing "look sword" to find items the player is carrying. Also extended `findFeature()` and `findContainer()` to include personal discoveries when `playerId` is provided.

- [x] **Monster spawn not broadcast to room**: Added broadcast to `handleSpawn` admin command and feature-triggered spawns. When a monster spawns, other players in the room see "A <monster> emerges from the shadows." Admin spawn broadcasts via CommandResult, feature-triggered spawns broadcast via the command handler in `commands/index.ts`.

- [x] **Split XP for group combat**: Implemented pooled XP system for group combat. When multiple players fight the same monster, XP is calculated by: (1) summing each participant's solo XP (based on their level vs monster level), (2) averaging the pool, (3) applying a group multiplier. Multiplier formula: `(1 + 0.2 * min(participants-1, 4)) / participants` gives 100% solo, 60% each for 2 players, ~47% for 3, 40% for 4, 36% for 5+. Higher level players benefit from helping lower level players (they get more XP than fighting same-level monsters in a group). Players who flee don't get XP (removed from monsterTargets). Updated `monster_death` event to include `xpAwards` array with per-player XP. Socket handler sends personalized messages: killer gets "You defeat", helpers get "You helped defeat". Added unit tests for `calculateGroupXpMultiplier()` and group XP calculation scenarios.

- [x] **Monster respawn system**: Implemented per-monster respawn tracking. Instead of deleting monster instances on death, they're marked with `killedAt` timestamp and `currentHp = 0`. Added `respawnSeconds` field to monsters table (default 120s for testing, can be set per monster type). On room enter, `SpawnService.checkRoomRespawns()` checks for dead monsters whose respawn time has passed and revives them (resets HP, clears killedAt). Each monster tracks its own death time, so killing 3 monsters at different times means they respawn at different times - no "bursty" respawns. Updated `getRoomWithContents` to filter out dead monsters (currentHp <= 0). Broadcasts "A <monster> emerges from the shadows." when monsters respawn.

- [x] **Library-based spell learning**: Added Village Library room (west of Town Square) with spell book features for Missile and Mend spells. Spell books use `teachesSpellId` field and `learn_spell` effect type. Learning checks INT requirement, spell capacity, and whether already known. Added `triggerAliases` field to features for disambiguation - "read book" or "read spellbook" matches both books and prompts "Read which one?" with options. Feature disambiguation returns `FeatureMatchResult` union type: `found`, `ambiguous`, or `none`.

- [x] **WIS → Perception/Discovery**: Implemented WIS-based perception system for discovering hidden features. Added `perceptionDC` and `perceptionHint` fields to features and containers tables. Created `search` command that rolls d20 + WIS modifier vs feature's perceptionDC - success triggers the feature interaction, failure shows failureMessage. Added passive perception on room entry: when entering a room, checks features with perceptionDC against passive perception (10 + WIS modifier) and shows perceptionHint for features the player notices but hasn't discovered yet. Updated seed data with perceptionDC values for mushroom ring (DC 10), merchant stalls (DC 12), cobblestones (DC 8), undergrowth (DC 12), and underwater search features (DC 14).
